Поиск имеет два движка за общим интерфейсом `SearchEngine`: **OpenSearch** (production) и **PostgreSQL FTS + pg_trgm** (резерв, локальная разработка, тесты). Выбор — `SEARCH_DRIVER`.

## 2. Почему модульный монолит
Один деплой-артефакт API, домены разделены по папкам `apps/api/src/modules/*` с явными сервисами. Горизонтальное масштабирование — репликами API и worker (состояние в PostgreSQL/Redis, WebSocket через Redis adapter). Выделение сервисов (поиск, чат, платежи) возможно без переписывания: модули общаются через сервисные интерфейсы и очередь заданий. Подробнее — `DECISIONS.md` (ADR-001).

## 3. Модули backend

| Модуль | Ответственность |
|---|---|
| `auth` | Регистрация email+пароль (argon2id), подтверждение email, SMS-вход, восстановление пароля, JWT access (15 мин) + ротируемый refresh (30 дней, обнаружение повторного использования), сессии, выход со всех устройств, защита от перебора |
| `users` | Профиль, публичная страница, настройки уведомлений, push-токены, блокировка собеседников, удаление аккаунта (обезличивание, 152-ФЗ) |
| `organizations` | Профили компаний (ИНН с проверкой контрольной суммы, ОГРН), сотрудники |
| `catalog` | Дерево категорий и регионов, характеристики (типизированные, зависимые справочники), наследование характеристик, валидация значений |
| `media` | Загрузка, проверка сигнатуры, антивирус (ClamAV), перекодирование и варианты изображений (sharp), подписанные ссылки на приватные файлы |
| `listings` | Объявления: CRUD, жизненный цикл (машина состояний), квоты бесплатных публикаций, автомодерация, статистика, телефон по запросу |
| `search` | Поиск/фильтры/гео/карта/автодополнение, синонимы, индексация, сохранённые поиски и уведомления |
| `engagement` | Избранное, сохранённые поиски, детерминированные рекомендации, история просмотров |
| `chat` | Диалоги по объявлениям, сообщения, статусы доставки/прочтения, вложения, архив, поиск, Socket.IO-шлюз |
| `notifications` | In-app + email + push (+SMS) с учётом настроек каналов |
| `community` | Отзывы (правила допуска), жалобы (автоповторная модерация по порогу) |
| `orders` | Заказы, резервирование количества, жизненный цикл, доставка (абстракция провайдера), авто-завершение/отмена |
| `payments` | Платёжные провайдеры (mock, ЮKassa), webhook, сверка, возвраты, двойная запись (ledger) |
| `billing` | Каталог платных услуг, покупки, продвижение (bump/highlight/premium), пакеты, PRO/аналитика, бонусы, реклама (erid) |
| `admin` | Административный API (RBAC), модерация, аудит, аналитика, настройки |
| `health` | `/health/live`, `/health/ready`, `/metrics` |

Инфраструктурные сервисы (`apps/api/src/infra`): `JobsService` (BullMQ / inline), `StorageService` (S3/локально), `MailService`, `SmsService`, `PushService`, `RealtimeService` (Redis emitter), `AuditService`, `SecurityEventsService`, `SettingsService`, `RateLimitService`.

## 4. Ключевые потоки

### 4.1 Публикация объявления
`POST /listings` (черновик) → `POST /listings/:id/submit` → полная валидация (обязательные характеристики, подтверждённый контакт) → списание квоты (бесплатный лимит категории / оплаченный слот, `SELECT … FOR UPDATE`) → `draft→moderation` → автомодерация (стоп-слова, контакты/ссылки, ценовые аномалии, дубли, доверие к аккаунту, ручная категория) → `approve` (сразу `active`) / `reject` / очередь модератора. После `active` — задание `search.index`.

### 4.2 Сообщения
Клиент подключается к Socket.IO (`auth.token` = access-токен), входит в комнату `user:{id}`. Отправка — `message:send` с `clientMessageId` (идемпотентность при повторе после обрыва) или REST. Сервер сохраняет в PostgreSQL, рассылает `message:new` обоим участникам через Redis (работает между репликами и из worker), push получателю. Прочтение — `conversation:read` → `message:read` отправителю. После переподключения клиент досинхронизирует историю по REST.

### 4.3 Заказ и оплата
`POST /orders` (Idempotency-Key) → в транзакции: блокировка объявления, резерв количества, заказ, запись платежа → регистрация платежа у провайдера (вне транзакции) → редирект на `confirmationUrl` → провайдер шлёт webhook → проверка подлинности (HMAC для mock; IP + повторный запрос статуса для ЮKassa) → дедупликация по `provider_event_id` → статус платежа запрашивается у провайдера → в транзакции: статус платежа, проводки ledger (`provider_clearing` / `seller_payable` / `platform_revenue`), переход заказа `pending_payment→created`. Отмена оплаченного заказа → автоматический возврат и обратные проводки.

### 4.4 Выдача: органика и платное продвижение
Органическая выдача сортируется только по релевантности/дате/цене/расстоянию. Премиум-объявления показываются в **отдельном помеченном блоке** (до 3, ротация по часу), выделение — визуальное, поднятие меняет дату для сортировки «по дате». Платные услуги не влияют на ранжирование релевантности.

### 4.5 Рекомендации
Детерминированный алгоритм: веса интересов по категориям (просмотр +1, избранное +3, контакт +5, ежедневное затухание ×0.9) → свежие объявления топ-3 категорий в городе пользователя, без своих и просмотренных → добор популярными. Хранятся только агрегаты; пользователь может очистить историю. ML не используется.

## 5. Безопасность (сводка)
JWT с проверкой версии токенов и статуса пользователя (кэш Redis 60 с, сброс при изменениях) • refresh в httpOnly SameSite=Strict cookie + двойная отправка CSRF-токена для веба • RBAC (`packages/shared/src/permissions.ts`) на каждом админ-эндпоинте • IDOR: проверки владельца/участника, чужой объект → 404 • rate limiting на Redis (глобально по IP + именованные лимиты) • блокировка входа после 5 неудачных попыток • helmet, CSP для API, `nosniff` для файлов • события безопасности в `security_events` • аудит админ-действий. Подробно — `docs/SECURITY.md`.

## 6. Масштабирование
- API и worker — stateless, горизонтально (HPA в Helm).
- WebSocket — Socket.IO Redis adapter; sticky-сессии не обязательны при транспорте websocket.
- PostgreSQL — вертикально + реплики чтения (поиск можно переключить на OpenSearch, снимая нагрузку); партиционирование `messages`/`audit_logs` по времени — при росте (см. DATABASE.md).
- OpenSearch — кластер с репликами (в Helm values), индекс — производная проекция, пересоздаётся `POST /admin/search/reindex`.
- Медиа — S3 + CDN.

## 7. Мультистрановость и языки
`regions.country_code`, валюта в объявлениях/платежах, локализованные подписи в `packages/shared/src/labels.ts` (машинные коды отделены от текстов), `users.locale`. Новый язык — словарь с теми же ключами; новая страна — регионы, платёжный провайдер и юридические тексты.
